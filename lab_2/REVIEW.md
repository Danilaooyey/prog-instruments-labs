## Замечания

### 1. Верификатор сообщает об ошибке через успешный код выхода

**Тип** · Ошибка интерфейса командной строки.

Если результат умножения отличается или входной файл не читается, программа печатает сообщение и завершается с кодом `0`. Поэтому, например, после `python matrinxMultiVerification.py && echo OK` команда `echo` выполнится даже при несовпадении матриц. Предлагаю возвращать `0` при совпадении, `1` при различии и `2` при ошибке ввода. В точке входа можно вызвать `raise SystemExit(main())`. [Проверка результата и обработка ошибок](https://github.com/Danilaooyey/parallel-programming/blob/4148e5b697d89647979f0f41df97416f973d09aa/lab1/matrinxMultiVerification.py#L21-L40).

### 2. Загрузчик не проверяет размер из заголовка

**Тип** · Недостаточная валидация входных данных.

Заголовок `2` и две строки по три числа сейчас дают массив формы `2 × 3`. Лишние строки игнорируются. Это мешает понять, что C++ программа записала повреждённый файл. При чтении предлагаю проверить количество чисел в каждой строке и отсутствие лишних непустых строк, а при ошибке указать путь и номер строки.

```python
for line_number in range(2, size + 2):
    values = file.readline().split()
    if len(values) != size:
        raise ValueError(f"{file_path}:{line_number}: expected {size} values")
    rows.append([int(value) for value in values])
```

[Чтение заголовка и строк](https://github.com/Danilaooyey/parallel-programming/blob/4148e5b697d89647979f0f41df97416f973d09aa/lab1/matrinxMultiVerification.py#L3-L18).

### 3. Одинаковые пути приводят к перезаписи первой матрицы

**Тип** · Ошибка обработки параметров.

Параметры `-m1 out.txt -m2 out.txt` принимаются без проверки. Обе записи проходят успешно, но в файле остаётся только вторая матрица. Предлагаю сравнивать пути до генерации, например через `Path(...).resolve()`, и выводить ошибку аргументов при совпадении. Для уже существующих файлов `Path.samefile()` также позволит распознать жёсткие ссылки. [Параметры путей и запись](https://github.com/Danilaooyey/parallel-programming/blob/4148e5b697d89647979f0f41df97416f973d09aa/lab1/matrixGenerate.py#L29-L44).

### 4. При записи в памяти одновременно находятся строки и весь текст файла

**Тип** · Лишние затраты памяти.

По умолчанию матрица содержит четыре миллиона чисел. Сначала функция накапливает все текстовые строки, затем собирает из них ещё одну большую строку. Предлагаю открыть файл, записать заголовок и последовательно записывать строки матрицы. Это сократит дополнительную память до текста одной строки и позволит сохранить текущий формат. [Подготовка текста матрицы](https://github.com/Danilaooyey/parallel-programming/blob/4148e5b697d89647979f0f41df97416f973d09aa/lab1/matrixGenerate.py#L4-L18).

### 5. Генератор и верификатор по-разному задают входные пути

**Тип** · Несогласованность командного интерфейса.

После генерации с `-m1 first.txt -m2 second.txt` верификатор всё равно открывает `matrix1.txt` и `matrix2.txt`. Если в каталоге остались файлы от предыдущего запуска, проверка будет выполнена для другого набора данных. Предлагаю добавить в верификатор параметры путей к обеим матрицам и результату, сохранив текущие имена как значения по умолчанию. [Пути в верификаторе](https://github.com/Danilaooyey/parallel-programming/blob/4148e5b697d89647979f0f41df97416f973d09aa/lab1/matrinxMultiVerification.py#L21-L25).
